中文文案去除 AI 寫作痕跡的自查指令。規則全部內嵌在本檔，單獨就能跑。可搭配 `/no-ai-trace` 使用，那支涵蓋英文的通用 17 條規則。

核心原則：人寫中文，是在講清楚一件事。AI 寫中文，常在表演「我很謹慎」「我很有架構」「我很專業」。

適用對象：以中文為主的對外或準對外產出，例如 README、zh-TW 說明、訊息、報告、中文 PR 描述。只要有第三人會看到，哪怕只是給主管的進度匯報，也跑完整檢查。

用法：
- `/no-ai-trace-zh` 檢查對話中最近一次中文文案輸出
- `/no-ai-trace-zh [貼上文字]` 檢查指定文字
- `/no-ai-trace-zh <檔案路徑>` 檢查指定檔

步驟：

1. 確認要檢查的文字。
   - 指令後有貼文字或給路徑：檢查那段或該檔。
   - 沒有：檢查對話中最近一次中文文案輸出，包含剛寫入或編輯的檔案。
   - 網頁上有切換狀態、或由 JavaScript 動態產生的文字：每個狀態都用 headless Chrome 的 `--dump-dom`（網址帶不同 hash 或參數）抽出可見文字再掃。只讀 HTML 原始碼，會漏掉切換後才出現的說明。

2. 先跑機械 grep（見下方「機械 grep」）。每個命中都要逐一判斷，命中只是候選。

3. 掃描 Part Z（Z1 到 Z11），再掃基礎檢查（G1 到 G6）。語意型的樣式逐句判斷。

4. 跑檔尾的「輸出前自查」。網頁另外截圖看排版，機械掃描 0 違規不代表通過。找三種：一段或一格塞超過 3 件事（拆條列）、表格欄位窄到標題斷成很多行（加欄寬）、備註用分號疊好幾句（只留結論）。

5. 輸出格式（固定）：
   - 第一行：「共發現 N 處違規」，N 為 0 也要說。
   - 每條：`[Z# 或 G# 規則名稱] 原句`，接著給建議改法。
   - 「不是…而是…」逐筆判斷：修辭抬升算違規。資訊型的劃界（例如「本 repo 不做 X」）標「保留」，並用一句話說明。
   - 最後一行：語氣總評，一句話。像人在交代事情，還是像 AI 產品說明或勸退文？

6. 0 違規時，語氣總評也要過，才輸出「✓ 通過」。

7. 讓規則持續校準：當用戶說某句「像 AI」，或貼出他親手終修過的定稿，把原句與定稿版本（含對應規則編號）記進用戶自己保存規則的地方。真實的修正比單純一句「這句不對」更能校準改寫方向。

## 機械 grep

對目標檔跑下列指令。命中一律視為候選，放回上下文判斷。

- 元標籤：`誠實的範圍|重要說明|溫馨提醒|特別注意|核心洞察|一句話總結`
- 對比句型：`不是.{0,20}而是|並非.{0,20}而是|不只是.{0,20}而是|與其說.{0,20}不如`
- 假正式過渡：`值得注意的是|需要強調的是|綜上所述|總的來說|不得不說`
- 動詞墊字：`進行(處理|優化|分析|檢查|評估)`
- 破折號，含中文連寫的雙破折號：`grep -n "$(printf '\xe2\x80\x94')" 檔案`
- 括號補述：全形 `（[^）]{1,80}）` 與半形 `\([A-Za-z ]{2,}\)`。命中逐一判斷，資訊型補述可標「保留」，程式碼註解與變數（如 `(el)`）排除。範圍放寬到 80 字，是因為含網址的長括號會漏過短範圍。

## Part Z：中文紅旗

以下樣式一出現，就刪除或重寫。

### Z1. 元敘事標籤（最嚴重之一）

用小標題或引用框宣告自己的寫作姿態，而不是直接寫內容。典型字樣：

- 誠實的範圍、誠實講、坦率地說、必須先說清楚
- 重要說明、溫馨提醒、特別注意、特別聲明
- 核心洞察、關鍵收穫、一句話總結、快速總覽
- 給讀者的話、在開始之前

- (X) `> **誠實的範圍。** 這個工具目前沒有離線模式…`
- (X) `## 重要說明`
- (X) `坦率地說，這個工具有極限。`

改法：刪標籤，把限制或重點直接寫進內文一句。需要分段就用中性標題（如「範圍」「限制」「怎麼用」），不要自我標榜誠實。

- (O) `這個工具目前沒有離線模式，資料需要連網同步。`

### Z2. 否定前提對比（中文高頻）

「不是 A，而是 B」這類句型在中文的加強版。命中即改，除非是資訊型界定（見下方例外）。

- 不是…而是…、並非…而是…、與其說…不如…、不在於…而在於…
- 不是 X 的替代，而是 Y（開場就用，等於勸退腔與對比腔疊加）

- (X) `這不是 Excel 的替代品，而是互補工具。`
- (X) `我們不是在追求速度，而是在追求品質。`

- (O) `Excel 仍負責日常試算，這個工具專做資料清洗。`
- (O) `我們優先品質。`

否定補尾也算：正面講完之後，再補一句「不會 X／不是 Y」。即使是在說明款項由誰退，也一樣違規，這句通常可以直接刪。

- (X) `檔案會存在你自己的資料夾，不會上傳雲端。`
- (O) `檔案會存在你自己的資料夾。`

例外（可保留，檢查時標「保留」）：真的在劃界、對規格說「不做 A」時，用平述即可，不必硬套「不是 A 而是 B」句型。例：`本 repo 不做 memory 同步。`

### Z3. 翻譯腔／公文腔

- 進行 + 動詞：`進行處理`、`進行優化`、`進行分析`，直接用動詞
- 具有…的能力／具備…功能，改成 能…、可…
- 在…方面、就…而言 當句首墊話
- 「針對…進行…」「基於…進行…」

- (X) `本工具可針對查詢進行多角度分析。`
- (O) `多角度搜尋後再回答。`

給本人看的頁面，也不要寫成第三人稱的工作紀錄口吻，更不要混進開發紀錄。

- (X) `使用者已用地圖核對過這條路線，並於週六實際跑過。`
- (O) `路線用地圖核對過，週六實跑：5 km、30 分。`

### Z4. 假正式過渡與 hedge

- 值得注意的是、需要強調的是、不得不說、總的來說、總體而言、綜上所述、由此可見
- 在某種程度上、從某種意義上說、相對而言（無比較基準時）

- (X) `值得注意的是，備援伺服器通常比主機慢。`
- (O) `備援伺服器通常比主機慢。`

### Z5. 開場暖場／自我矮化

- 在當今…、隨著 AI 的發展…、不可否認…
- 「先講結論再展開」當空話標題，其實沒有真的結論先行
- 一開始就連寫「做不到／不是替代／限制很多」，當成賣點開場
- 預告式開場加冒號：`接下來說明設定步驟：`、`要注意兩件事：`

直接刪，從讀者要做的事或得到的好處起筆。

### Z6. 空泛抬升

- 不僅…更…、不但…還…（兩半句資訊量一樣時）
- 全面、深度、顯著、有效提升（無數字或例子）

- (X) `這不僅提升效率，更能顯著改善品質。`
- (O) `同樣的問題，加前綴後會標來源日期、分開事實與意見。`

### Z7. 模板序號腔

「首先…其次…最後…」僅在步驟真的有順序時用。若只是修辭骨架、每段都套，改成主題小標或直接條列重點。

### Z8. 文件開場套話

- 本文以 A 作為 B 的簡稱（改更短，或在首次出現時直接定義）
- 本專案旨在…、本倉庫的目標是…

- (X) `本文以 CLI 作為命令列介面的簡稱，以 PR 作為合併請求的簡稱。`
- (O) `文中 CLI = 命令列介面，PR = 合併請求。`

或首次寫全名後，用括號放縮寫即可。

### Z9. 括號補述、破折號

中文文件同樣禁用破折號字元（U+2014），含中文連寫的雙破折號。括號補述能併進主句就併，否則另起一句。

中文詞後配英文原文或術語對照，例如 `同儕帶領（peer-led）`、`跨部門協作（cross-functional collaboration）`，同樣算違規。即使功能只是註解術語，一樣讓主句變重。中文詞本身已達意時，直接刪掉英文括號。真的需要保留原文術語（專有名詞、業界慣用縮寫）時，改成單獨用英文原文，不要中英並列。

- (X) `改用同儕帶領（peer-led）取代高價講師或活動公司`
- (O) `改用同儕帶領取代高價講師或活動公司`

介面文字、標籤、表頭、按鈕文字、清單名稱、捷徑選項、聊天回覆一樣適用。條件或時間改寫在前面，例如「週五前繳費」，不要寫「繳費（週五前）」。網頁說明一段塞了 6 件事，就拆成條列，每條「主題：一句話」。

例外（可保留，檢查時標「保留」）：括號本身是記號的寫法。例如路線式子 `A 市→B 市（停留）→C 市`，括號標出哪一站停留，拿掉就看不出停在哪。路線式子以外的停留說明照常改寫，例如 `→B 市（停留，最長 3 天）→` 拆成 `→B 市（停留）→目的地，B 市最多停 3 天`。

### Z10. 結論段勸退腔

結尾只剩「所以別指望／只留一件小事／其餘一切仍靠 X」，讀者就走了。

- (X) `留著它做一件事就好。其餘一切，Word 仍是主力。`
- (O) `日常編輯用 Word，需要批次轉檔時用這個工具。`

### Z11. 假對稱「能／不能」

「能做到的」「做不到的」各開一章、等長並列，讓限制跟賣點搶版面。限制改成文末一小段「範圍」即可，不要對半開。

## 基礎檢查（G1 到 G6）

這幾種通用樣式在中文裡也會出現。寫在這裡，是為了讓本指令不依賴任何其他檔案。

### G1. 反問自答

- (X) `這對交易者意味著什麼？意味著更快的成交與更低的成本。`
- (O) `交易者拿到更快的成交與更低的成本。`

### G2. 「X 是真實的」確認句

- (X) `這個需求是真實存在的。` `這個缺口是真實的。`
- (O) `半年內需求成長了三倍。`

換成具體數字或事實。

### G3. 碎句排比

- (X) `新的團隊。新的規則。新的賽局。`
- (O) `新團隊帶來新規則，賽局也不一樣了。`

併成一句，或三句只留一句。

### G4. 二元框架加感傷代價句

- (X) `一場會議，兩種結果，都有代價。`
- (O) `偏鴿的結果，三天內大盤可能漲 4% 到 6%。偏鷹的結果，成長股當天跌約 3%。`

改成機率或幅度。

### G5. 並列主詞拆句

- (X) `甲隊晉級。乙隊晉級。`
- (O) `甲隊和乙隊都晉級了。`

### G6. 行話堆疊

- 賦能、抓手、閉環、打造生態、全方位、一站式，堆在一起卻沒有具體主張
- (X) `本平台賦能開發者，打造全方位協作閉環。`
- (O) `開發者可以在同一個頁面寫程式、審查、部署。`

## 輸出前自查（每次必過）

- 元標籤：有沒有「誠實的範圍／重要說明／溫馨提醒」這類標籤？
- 對比：有沒有「不是…而是…」或「不只是…而是…」開場或連用？有沒有在完整句子後補否定句尾？有沒有預告式開場加冒號？
- 公文腔：有沒有「進行 X」「具有…能力」「值得注意的是」？
- 開場：是直接講用途，還是先免責、先勸退？
- 限制：限制有沒有被抬成跟賣點同等的大章？
- 暖場與空泛抬升：有沒有「在當今…」「不僅…更…」「全面／深度／顯著」卻沒有數字支撐？
- 序號：「首先…其次…最後…」用在沒有真實順序的地方嗎？
- 括號與破折號：有沒有破折號？有沒有括號補述，包含中文詞後配英文原文？記號型括號可保留。
- 基礎檢查：有沒有反問自答（G1）、「是真實的」確認句（G2）、碎句排比（G3）、二元代價句（G4）、並列主詞拆句（G5）、行話堆疊（G6）？
- 整體語氣：讀起來像人在交代事情，還是像在寫「負責任的 AI 產品說明」？
