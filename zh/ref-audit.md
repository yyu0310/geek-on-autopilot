資料夾搬移、改名、合併、刪除**之前**先跑。它會把所有可能寫死舊路徑的地方掃一遍，免得一週後才發現權限規則失效、排程炸掉或文件死鏈。

用法：`/ref-audit projects/old-site`（可給多個字串；改名案舊名新名都要給）

設定：`ref_audit.py` 與 `relink.py` 放在 repo 根目錄。下面的指令預設你在根目錄執行，否則請改用完整路徑。兩支都只用標準函式庫。下面的 `sed -i ''` 是 macOS（BSD sed）語法，Linux 要用 `sed -i`，而且預設的 launchd 資料夾只存在於 macOS。

## 步驟

1. **確認掃描字串。** 用戶給的路徑片段；若是改名案，舊名新名都掃。

2. **五個掃描域一個都不能省，漏一個就是斷鏈的來源。** 最會炸的往往不是文件。
   - **專案目錄**：`--root` 底下（預設目前目錄）的 `*.md *.py *.sh *.gs *.json *.plist`，略過 `._*` 檔、`node_modules` 與 `.git`
   - **Claude Code 設定**：`<root>/.claude/settings*.json` 與 `~/.claude/settings*.json`。權限白名單會寫死路徑，搬移後規則默默失效。
   - **Claude memory**：該專案的 memory 資料夾，記憶檔會指向路徑。腳本依 `--root` 推導資料夾名稱，但 Claude Code 是依你啟動它的資料夾命名。兩者不同、或你不確定時，請明確加 `--memory-dir`，否則這個域會靜默回報沒有命中。
   - **`~/.claude/commands` symlink**：每個連結指向哪裡
   - **排程**：`~/Library/LaunchAgents` 的 plist（略過 `com.apple*`）、你的 crontab，以及同步工具的設定檔（用 `--sync-config` 帶入）。排程或同步工具還指著舊位置，搬完會悄悄失敗。

   執行：

   ```bash
   python3 ref_audit.py "old-name" "new-name" --root /path/to/project --out /path/you/choose/ref_audit_report.md
   ```

   輸出貼進對話。旗標：`--no-gs` 略過 `.gs` 檔；`--no-launchd` 略過排程域（plist、crontab、同步設定）；`--claude-dir`、`--memory-dir` 與 `--launchd-dir` 用來指向非預設位置。兩個略過旗標的判斷準則：只有確定標的不可能被 Apps Script 檔或排程 job 引用（例如純筆記資料夾）才加；腳本或排程可能引用就兩個都不要加。

3. **寫出稽核清單**到用戶指定的位置（`--out`），每個檔標命中數。別放進你的捕捉區或收件匣，機械報告塞進去只是雜訊。

4. **逐個命中分類**：「活檔要改」或「歷史檔保留」。舊工作日誌、封存設定、稽核清單本身通常保留舊路徑。
   - `settings.local.json` 的命中要再分兩類。**權限規則**（如 `Read(...)`）是活檔，要改；**一次性指令記錄**（如 `Bash(/bin/mv ...)`）是歷史，無害不用改。看行內容就分得出來。

5. **sed 驗證要用完整舊路徑。** 新路徑包含舊字串時（例如 `drafts` 改成 `archive/drafts`），sed 前後的 grep 計數不會變，看起來像沒改到。要用含上層資料夾的完整舊路徑 grep，或直接抽查改後內容。

6. **設定表裡的相對路徑列，用「存在性」驗證，不用字串。** 表裡像 `scripts/README.md` 這種列根本不含被搬資料夾的名字，用名稱映射抓不到，最後的 grep 也看不見。搬完後對每一列跑 `[ -e ]` 或 `ls`。

## 踩坑

1. **URL 編碼變體。** Markdown 連結會把空格寫成 `%20`，例如 `[Notes](../Q3%20Plan/notes.md)`。標的名稱含空格時，純字串掃描會漏，sed 也不會替換。`ref_audit.py` 會自動多搜 `%20` 寫法與完整百分號編碼寫法。替換時兩種寫法都要 sed，最後再對整棵樹重新 grep 終驗；在目標清單內卻漏掉 sed 的檔案，會在這一步現形。

2. **前綴與簡稱變體。** 標的名帶常見前綴或限定詞（`Team Handbook`）時，文件常用較短的簡稱（`Handbook`）。只掃全名會漏，而漏掉的往往是關鍵活檔，例如某份設計筆記寫著「Handbook 資料夾，留原地不搬」，之後就誤導下一次搬移。要補掃去掉前綴的核心名，排除全名命中後，人工看剩下的差異。

3. **名稱撞專有名詞。** 資料夾名剛好也是平台或產品名（資料夾叫 `Atlas`，市面上也有叫 Atlas 的產品）時，大部分命中是在提產品，不是路徑。先掃名稱，再補掃含上層資料夾的完整路徑（`research/Atlas`、名稱有空格時的 `%20` 寫法、以及 `Atlas/子資料夾`）。活檔判定以完整路徑掃描為準；名稱掃描多出來的命中，用 `sed -n 'Np'` 抽一行確認是專有名詞就好，不必逐檔改。

4. **遵守 `.gitignore` 的 grep。** ugrep、ripgrep 這類工具預設跳過 `.gitignore` 列出的檔案，手動重新 grep 可能把沒乾淨的樹判成乾淨。加 `--no-ignore-files`（ugrep）或 `--no-ignore`（ripgrep），或直接重跑 `ref_audit.py`：它自己走訪目錄，不受 `.gitignore` 影響。

## 若接著執行搬移（用戶確認後）

照安全搬移流程：

0. **稽核清單不是剛產出的就先重掃。** 稽核到搬移之間新寫的檔案也可能引用舊路徑，舊清單會漏。
1. 用 `cp -R` 複製（不用 `mv`），再比對來源與目的的檔案數（排除 `._*`）。
2. 用 `sed -i ''`（macOS 語法，Linux 用 `sed -i`）逐檔改引用，印出每檔改前改後的命中數。
   - **層數會變的搬移改用 `relink.py`。** 子資料夾上移或下移一層、或改名又搬回時，字串取代算不對 `../` 的層數。搬完執行：

     ```bash
     python3 relink.py --root /path/to/affected/parent --map "/old/abs/path=/new/abs/path" --also /path/to/live/file/outside.md
     ```

     兩個方向的斷鏈它都修：別的檔案連到舊位置的，以及被搬檔案自己往外連的。保留 `<>` 或 `%20` 的原寫法，`--dry-run` 可先預覽。
3. 終驗：重新 grep 舊路徑，殘留應該只剩「歷史檔保留」那份名單。再跑 `python3 relink.py --root /path/to/parent --check`，斷鏈必須是 0（exit 4 代表還有）。只查含被搬資料夾名稱的連結，會漏掉指向腳本檔的那種。
4. 這時才對來源 `rm -rf`，之後驗證目的地存在。
5. 同步更新資料夾地圖或索引文件，並在專案工作日誌記一筆搬移。
6. 順手檢查目的地有沒有同用途的舊資料夾或空殼。搬移是抓殭屍資料夾的最佳時機：確認裡面沒內容就清掉，並更新索引。

## 注意

- `ref_audit.py` 只回報 `檔案:行號`，不印命中的行內容，所以即使命中發生在名稱像憑證的檔案裡，終端機與 `--out` 檔也不會洩漏任何東西。
- 掃描是腳本做的機械活，零 token。分類是判斷層的工作，中階模型就夠用。

腳本 exit code 慣例：0 成功／2 外部指令或 I/O 失敗／3 檔案或資料夾不存在／4 硬門檻失敗／5 缺少相依工具。
