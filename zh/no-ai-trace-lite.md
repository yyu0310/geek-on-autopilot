內部文件輕量自查，是 `/no-ai-trace` 的精簡版。

適用：只有你和團隊看的內部工作文件，例如提案、工作日誌、架構文件、派工檔，新落檔或大幅改寫後跑。對外產出，例如文章、README、PR、comment、訊息、講稿，不用這個，改跑完整版 `/no-ai-trace`。給主管的訊息也算對外，因為有第三人會看。

用法：
- `/no-ai-trace-lite <檔案路徑>` 檢查指定檔案
- 沒給路徑 → 檢查本次對話最近寫入或大幅修改的內部文件

步驟：

1. 機械掃描。實際跑 grep，以輸出為準：

````bash
grep -n "$(printf '\xe2\x80\x94')" "<檔案>"                                  # 破折號，內部文件同樣禁用
grep -niE "not (just|only|merely) |, not [a-z ]{1,30}, but |不是.{0,15}而是" "<檔案>"  # 否定前提對比句，中英文都掃
grep -n '^```' "<檔案>"                                                     # 非程式內容用 fenced block 即違規
````

真程式碼或終端指令用 fenced block 沒問題，其他內容改用清單、表格或箭頭串。

既有檔案只改局部時，先取本次新增的行再掃，避免誤報舊文。例如跑 `git diff -U0 "<檔案>" | grep '^+'`，再對輸出套用同樣的 pattern。舊文的違規不歸本次修，但改到的行若帶出舊違規，順手修掉。

2. 語意快掃。只看這四種，不做 17 條全檢：
   - 暖場開場：第一段是否直接進正題
   - 翻案敘事：是否保留舊結論再辯證翻案，筆記只寫當前正確做法並附日期
   - 碎句排比：連續超短句堆疊戲劇感
   - 括號補述：解釋是否塞進括號，改用逗號或冒號順順講出來。價格、日期、連結這類功能性括號保留

3. 輸出（固定格式）：
   - 第一行：「共發現 N 處」，0 也要說
   - 每處：規則、行號、原句，再接建議改法
   - 對比句命中要逐筆判斷：修辭強調型算違規，資訊型（界定範圍、說明取捨）不算，標「保留」並說明原因
   - 明顯的直接修，存疑的列給用戶裁決

規則全集與例句在 `/no-ai-trace`。本指令只是機械子集加內部文件的幾項檢查，規則不重複維護。
